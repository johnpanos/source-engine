# FSR 4.1.1 initial lab implementation — 2026-10-03

The isolated `codex/fsr-temporal` branch implements the initial provider and
measures real FSR dispatches on the laptop's Radeon 8060S (RADV STRIX_HALO,
Mesa 26.2.3, Vulkan 1.4.354). This is a lab checkpoint, not an in-game FSR
selection or RFC 0019 qualification. The requested game experiment is
1280×720 reconstruction to 1920×1080 with MSAA off for that run; it still
needs the game input and presentation integration. The saved High profile
remains native 1920×1080 with 4× MSAA. The 120 FPS target remains explicit;
a measured miss is advisory for FSR selection and release.

## Ownership and implementation

`render.pass.temporal` owns per-view history metadata and graph placement.
The producer supplies scene/view/eye/destination/full recursion-chain identity,
frame sequence and explicit discontinuity. It rejects missing motion,
nonfinite values, stale sequences, aliased resources and incompatible extents
or formats. Metadata commits only after successful submission. Reset, gaps,
resize, exposure change and device epoch change begin new history.

`render.device` supplies the provider-neutral recording port; the private
`render.device.vulkan` adapter maps its four textures to FSR. Its graph pass
reads single-sample RGBA16F linear color, D32 depth and RG16F motion and writes
RGBA16F output. Motion is unjittered current-to-previous render-pixel displacement.
Jitter is in render pixels. The initial provider uses automatic exposure, the
normal INT8 model, no sharpening, and supports output extents up to 3840×2160.
Frame delta is validated but this pinned upstream runtime has no delta input.
The full camera/depth convention and mask capability contract remains open.

The opt-in `--render-fsr411` build negotiates required GPU features before
creating the lab device. Without this option the provider reports unsupported.
The adapter keeps upstream constant slots and private history storage alive
behind actual completion tokens. Eight outstanding slots are bounded; a ninth
is refused until one completes. Reset/resize can allocate an independent
context while the previous one is still in flight. A failed dispatch aborts
submission; abandoned recording invalidates its history. Host sections are
explicitly refused until their replay path supports this dispatch.

The two new gitlinks pin the upstream runtime and Vulkan headers. The runtime
is the unofficial `johnpanos/FSR-4.1.1-linux` INT8 port at
`46a56a66b639d4e3f84033640d1e51a8655ebac4`; headers are
`c46850864f4661461b0f6cb9922c058ffea4915e`. Waf verifies both revisions and tracked
cleanliness. Original upstream notices remain: runtime GPL-2.0-or-later,
AMD shaders/model assets under their separate MIT exception. No AMD endorsement
or equivalence to its signed distribution is claimed.

## Evidence and limits

The shared registry installs `render.lab.temporal-fsr411` and its sensitivity
row. The positive suite passes 54 checks for twelve frames, including finite
output, history metadata, exact reset-versus-fresh output, independent histories,
failed recording recovery, held GPU submissions, bounded constant-slot reuse,
reset with work outstanding and provider teardown before GPU completion.
The seeded retained-history defect triggers exactly three reset/isolation
comparison failures; its sensitivity row passes one detection check. Validation
reports zero warnings/errors including teardown. Healthy-device `Recover()`
is only a no-op check; real loss/recovery remains unverified.

The analytical scene has a moving camera and independently moving foreground
rectangle over diagonal detail, with known depth/motion and Halton jitter. It
is not a rendered game, skinned-model, glass, cutout or portal input oracle.
Static readback is finite and visibly plausible; no matched motion-clip quality
acceptance is claimed.

The retained local evidence is under
[`quality-results/fsr-2026-10-03`](../quality-results/fsr-2026-10-03/), including
shared runner JSON with source/dirty digest, dependency pins, compiler and GPU
facts. GCC is 16.2.1, release configuration, strict C++20 core targets.

time, peak private memory and frame pacing are not measured. No Fold7 was attached;
mobile timing and support are unavailable. Missing product evidence is distinct
from an observed timing miss, which would be recorded without blocking FSR.

The existing Vulkan device regression passes 1,074 checks and its sensitivity
suite 21 checks with the optional provider disabled. Architecture full check,

38 style fixtures and the changed-file style check. Loader inventory adds only unused
vendor loader sites with explicit unbuilt classifications; runtime coverage is
unchanged. Target ownership verification requires all declared build trees;
this isolated lab tree alone cannot certify that portfolio-wide gate.

## Reproduction

From this worktree, initialize the declared submodules and install the existing
pinned shader toolchain using `tools/render/shader_toolchain.py build` if absent.
Use the clean pinned KTX source/build required by the existing tools composition.
This host used `/tmp/ktx-material-audit` and its `build` directory; those paths are
local cache locations, not required sibling repositories.

```sh
git submodule update --init thirdparty lib ivp box3d external/fsr411 external/fsr-vulkan-headers
python3 waf configure --tools --render-core-vulkan=on --render-fsr411 \
  --ktx-source-root=/tmp/ktx-material-audit \
  --ktx-build-root=/tmp/ktx-material-audit/build --build-type=release -o build-fsr
python3 waf build --targets=render_lab -j8 -o build-fsr
python3 tools/render/lab.py suite temporal --tree build-fsr \
  --render 1280x720 --output 1920x1080 --frames 300 \
  --dump quality-results/fsr-2026-10-03/quality-1080.pfm
```

The system validation layer 1.4.341 predates the mixed-dot shader extension and
is insufficient. These runs use ValidationLayers 1.4.365 at the revision pinned
by `external/fsr411/dependencies.json`, `873a4efbb27d214fe98482c1335c70fb7c18c196`.
Build that revision using its normal CMake workflow with `UPDATE_DEPS=ON`,
`BUILD_TESTS=OFF`, release configuration and an isolated install prefix. Its
known-good manifest pins its own dependencies. The local verified cache is
`dependencies/fsr-validation`; its layer JSON's library path is
`../../../lib64/libVkLayer_khronos_validation.so`, pointing to its own library.
The engine does not depend on another checkout's built validation library.

```sh
export VK_LAYER_PATH="$PWD/dependencies/fsr-validation/share/vulkan/explicit_layer.d"
python3 tools/quality/conformance.py check \
  --suite render.lab.temporal-fsr411 --suite render.lab.temporal-fsr411.sensitivity \
  --out quality-results/fsr-2026-10-03/conformance.json
python3 tools/render/lab.py suite temporal --tree build-fsr \
  --render 1067x600 --output 1600x900 --frames 12 --validate
python3 tools/quality/conformance.py check \
  --suite render.device.v2.vulkan --suite render.device.v2.vulkan.sensitivity \
  --out quality-results/fsr-2026-10-03/device-regression.json
```

## Open game boundary

The current game output hook consumes a display-referred backbuffer after the
legacy scene/UI stages. It does not supply pre-output HDR color, a per-view
motion image, committed previous object/bone transforms, coordinated jitter,
or portal correspondence. FSR cannot be enabled correctly by merely changing
that hook's output size. Required next work is the core input producer and its
lab oracle, then the private host feature/replay integration and placement
before output/UI. All contributing cohorts remain visible. Fake zero motion,
resetting every frame, or a spatial blit cannot qualify the requested temporal
game test. RFC 0019's full input, image, portal, loss, platform and product gates
remain open; no roadmap row is closed here.

Game integration continues in the [game checkpoint](0019-fsr-game-wip-2026-10-03.md);
the component measurements above do not qualify the game.
