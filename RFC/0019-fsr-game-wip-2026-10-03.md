## In-game input readback and resize recovery

`r_temporal_capture <unique-file-prefix>` captures the actual FSR color, depth,
motion and output, plus camera matrices and dimensions. It allows one pending
readback. The native host reports its actual submission token to the core on
the render sequence; failed submissions discard the capture, and successful
ones are read only after that token completes. The composition renderer's
null-device token is not a GPU fence for these images. Early captures using
that token were rejected. A successful JSON file accompanies the four raw
images; reusing a completed prefix is refused.

`tools/quality/temporal_capture.py` checks signed render-pixel motion against
independent depth/camera reprojection, or against zero for a paused scene.
Its sensitivity test rejects reversed signs, normalized units, stale zero
vectors, missing coverage and truncated input. Camera mode excludes the
viewmodel's separate depth range and is an oracle only for stationary surfaces.
This is diagnostic coverage, not proof that every game cohort supplies motion.

The initial fenced relit-map camera pan checked 857,333 world-depth pixels:
maximum reprojection error **0.03682 pixels**, all within the 0.25-pixel
tolerance. With `sv_pausable 1; setpause`, all **921,600 pixels**, including the
viewmodel, passed the stationary check (maximum **0.00006106 pixels**).
`host_timescale 0` does not pause this engine; that earlier run was rejected
as a stationary oracle. These accepted captures are retained as `pan-2` and
`paused-1` under the evidence directory.

Resize exposed two defects. A rejected frame left its acquire semaphore
signalled and its swapchain image unpresented; failure recovery now drains the
signal and retires that swapchain. The native GPU suite repeats six
abort/recover cycles and checks native submission notifications/tokens:
**157 checks, zero failures**, with validation required. Separately, the native
video-mode callback ran at `Present`, after the game had gathered a view using
the old extent. Main-thread mode changes now publish the new extent before
gathering that view. Four alternating 1600x900/1920x1080 game resizes completed
with no reconstruction/submission failures and returned to 1280x720 FSR input
and 1920x1080 output. The existing cube-view/2D-sampler validation errors persist.

The per-target motion-image cache now retains at most eight targets. Entries
from old frames/streams retire behind the native completion token; targets in
the current frame are not silently evicted. New streams clear motion even when
a failed submission did not advance the native frame counter. The final
four-resize capture reported eight retained motion targets.
